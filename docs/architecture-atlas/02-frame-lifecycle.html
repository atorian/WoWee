Streaming не содержит всей работы стриминга

Фаза Streaming опрашивает WorldLoader и loading scene, но terrain.update → processReadyTiles выполняется в Renderer::update, вызванном из Present. Название фазы не отражает всю её стоимость; смотреть только метрику Streaming недостаточно.

При анализе фризов раскрывать Present на terrain finalization, unload, animation и wait; не переносить вызовы без проверки зависимостей.

Events — не единственное место выполнения подписчиков

publish вызывает подписчиков сразу, например из Network или Game. Только post ждёт Events. FrameXML идёт отдельной FIFO в Interface; его обработчик может видеть более новое состояние игры, чем в момент публикации.

Указывать канал и фазу у нового события; синхронные подписчики переходов должны только записывать запрос. Стоимость publish относится к фазе отправителя.

Локальные бюджеты не дают общего потолка кадра

Сеть по умолчанию получает 4 мс в мире, 8 мс при входе и 12 мс при catch-up. Terrain finalize получает 2/8/16 мс, unload — ещё 8/16 мс. Это независимые лимиты; проверка между операциями не прерывает один долгий шаг. Это настройки времени, не измеренная длительность кадра.

Сопоставлять суммарные CPU-фазы с целевым временем кадра и отдельно отмечать overruns одной операции и ожидания GPU.

Что уже защищено. LOADING_WORLD проходит тот же цикл: сеть и simulation продолжаются, интерфейс показывает прогресс, готовность проверяется после Present. Мутации lifetime применяются после submit; Lua entry защищён фазой Interface. Закрытие окна может прервать кадр после Input или Interface.

Обязанности, границы и точный порядок
InputbeginFrame вычисляет dt; FramePlan уже выбран. SDL/pad читаются, Lua-backed input копится для Interface.
NetworkAuth/patch update, world socket transfer и ограниченный по времени opcode dispatch. Часть синхронных уведомлений возникает уже здесь.
GameСимуляция, reconnect, logout timeout, player/world client logic; подготовка запросов отображения.
EventsСнимок posted queue → подписчики. Новые post из обработчика остаются до следующего dispatch.
StreamingWorldLoader polling и прогресс, загрузочная сцена. Нет вложенного SDL/game/render цикла.
InterfaceВход интерфейса в мир, bindings, queued FrameXML, input, screens, ReloadUI, addon update, draw lists. При уходе — PLAYER_LEAVING_WORLD.
PresentPlayerView и передача мира, Renderer::update, terrain finalization/unload, animation + get, наблюдение readiness загрузки.
RenderRenderer beginFrame → frame-slot fence/timeline wait + acquire → запись проходов → secondary barriers → endFrame submit/present.
TransitionsЗапросы world entry, transfer, logout, reconnect, state. Только здесь создают/заканчивают мировые lifetimes.
PaceЕдинственное pacing место. Выбранный cap, VSync через presentation; затем Idle и отчёт frameFinished.
