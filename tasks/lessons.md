# Lessons

- 2026-10-10 — WoWee with StormLib: verify suggested CMake option combinations before recommending them. `WOWEE_BUILD_TESTS=OFF` fails because `wowee_link_stormlib` is defined inside the test guard but called by asset targets outside it. Until that scope is fixed, configure with `WOWEE_BUILD_TESTS=ON`; build only the required application targets to avoid building all tests.

- 2026-10-10 — Windows tools launched from WSL can inherit an incomplete `PATHEXT` (observed: `.CPL` only). Before a Windows build, ensure the child process environment includes `.COM;.EXE;.BAT;.CMD`; otherwise windres/cmd cannot launch GCC without an explicit `.exe` suffix. Keep this fix local to the build process.

- 2026-10-11 — A successful world authentication does not prove login works. For a client stuck awaiting `SMSG_CHAR_ENUM`, inspect the Warden exchange. Standard module `79c0768d657977d697e10bad956cced1` needs its exact hash reply and both new RC4 keys; do not assume WotLK servers tolerate an unanswered `HASH_REQUEST`. Verify module bytes, key and seed, send the reply before rekeying, and initialise check opcodes even when no external `.cr` exists. Continue through the first memory check and actual character list: this realm also gates on a byte read from its cached `WoW.exe`. Search the active expansion's `misc` directory; restricting lookup to Classic/Turtle misses an existing WotLK extraction. EZWoW additionally reads the runtime `.zdata` region at `0xDD1000` (216 bytes), which is zero on disk. Live inspection later found executable bootstrap code there, not ordinary DLL data; do not infer who populated it from a single memory read. A static PE image alone does not establish compatibility. Do not claim login is fixed before a real character list is received.

- 2026-10-11 — Per-server native library compatibility needs a verified ABI and matching process architecture, not just `LoadLibrary`. A generic host does not make an original WoW DLL compatible: inspect exports and fixed-address callbacks, keep adapters separate by auth endpoint, and distinguish a tested loader from a working realm integration. Do not present an infrastructure test as successful EZWoW login.

- 2026-10-11 — When the user chooses reusable protocol compatibility without server DLL sources, implement a built-in packet adapter and gather its actual exchange. A native DLL host alone does not satisfy that request. Do not ask again for unavailable SDK/source code or claim that a diagnostic parser completes login; verify the bootstrap, subsequent command framing and character list.

- 2026-10-11 — A private realm can install its bootstrap through an already-known stock opcode, so absence of unhandled-opcode logs proves little. EZWoW uses 27 short 0x2E9 packets with descending counts to deliver 216 bytes to a virtual bootstrap range; record bounded payloads before ordinary dispatch and translate the verified write semantics in session memory. Return current received bytes, never a captured snapshot, and verify the subsequent loader/character-list stage separately.

- 2026-10-11 — Verify internal callback-buffer prefixes against an actual packet before inferring wire fields. EZWoW CDataStore starts with a two-byte opcode; buffer+6 skips it plus the u32 extension command. Treating all six bytes as an excluded header misread 37 bytes of library metadata as executable code. Confirm lengths and instruction bytes with a real fixture before implementing a stage.

- 2026-10-11 — EZWoW drops an early character enumeration during extension setup: a single retry after 30 seconds returned seven real characters. Verify entry into the world separately: its next command 3 updates known title mask IDs (u8 operation, u16 count, u16 IDs); implement the semantic update rather than treating it as executable code or acknowledging fictional readiness.

- 2026-10-11 — Question marks in Cyrillic names can come from absent font glyphs even when network strings are intact UTF-8. Inspect the actual font cmap before changing encoding: the local FRIZQT/MORPHEUS lack Cyrillic while ARIALN contains it. Merge a font with the missing glyphs into both the client and FrameXML faces, retain font bytes for dynamic atlas loading, and check that existing Latin glyphs keep their metrics.

- 2026-10-11 — An extension double is not necessarily a timestamp: EZWoW command 5 stores extended copper and overrides the native Lua money accessor. Verify readers, constants and related events before assigning meaning; preserve the server balance separately from truncated stock fields, validate finiteness/integrality before casting, and clear it on character/endpoint changes.

- 2026-10-11 — A diagnostic 30-second retry became visible login latency. Replace arbitrary waits with a verified protocol boundary when available: EZWoW restores its file callback to RVA 0x419210 after the manifest and DBC checks. Queue one ordinary enumeration retry, dispatch it on the main thread after pending Warden replies, and discard it if the list already arrived or the session changed. Keep the timeout only as a fallback; never skip required server checks.
