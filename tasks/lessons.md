# Lessons

- 2026-10-15 — A visible FPS test used a settings-only profile, so the user's Isengard realm disappeared from the running client's server list. Preserve the complete active profile (including realm/account selection) for interactive test launches; keep stripped profiles confined to unattended runs. Restore the user's full profile immediately after measurement and verify the requested realm is present before leaving the client open.

- 2026-10-10 — WoWee with StormLib: verify suggested CMake option combinations before recommending them. `WOWEE_BUILD_TESTS=OFF` fails because `wowee_link_stormlib` is defined inside the test guard but called by asset targets outside it. Until that scope is fixed, configure with `WOWEE_BUILD_TESTS=ON`; build only the required application targets to avoid building all tests.

- 2026-10-10 — Windows tools launched from WSL can inherit an incomplete `PATHEXT` (observed: `.CPL` only). Before a Windows build or shader validation, ensure the child process environment includes `.COM;.EXE;.BAT;.CMD` and the required MSYS2 runtime on PATH; otherwise windres/cmd cannot launch GCC or a validator can fail to load its runtime. Check each native command’s exit code before claiming success. Keep these fixes local to the child process.

- 2026-10-11 — A successful world authentication does not prove login works. For a client stuck awaiting `SMSG_CHAR_ENUM`, inspect the Warden exchange. Standard module `79c0768d657977d697e10bad956cced1` needs its exact hash reply and both new RC4 keys; do not assume WotLK servers tolerate an unanswered `HASH_REQUEST`. Verify module bytes, key and seed, send the reply before rekeying, and initialise check opcodes even when no external `.cr` exists. Continue through the first memory check and actual character list: this realm also gates on a byte read from its cached `WoW.exe`. Search the active expansion's `misc` directory; restricting lookup to Classic/Turtle misses an existing WotLK extraction. EZWoW additionally reads the runtime `.zdata` region at `0xDD1000` (216 bytes), which is zero on disk. Live inspection later found executable bootstrap code there, not ordinary DLL data; do not infer who populated it from a single memory read. A static PE image alone does not establish compatibility. Do not claim login is fixed before a real character list is received.

- 2026-10-11 — Per-server native library compatibility needs a verified ABI and matching process architecture, not just `LoadLibrary`. A generic host does not make an original WoW DLL compatible: inspect exports and fixed-address callbacks, keep adapters separate by auth endpoint, and distinguish a tested loader from a working realm integration. Do not present an infrastructure test as successful EZWoW login.

- 2026-10-11 — When the user chooses reusable protocol compatibility without server DLL sources, implement a built-in packet adapter and gather its actual exchange. A native DLL host alone does not satisfy that request. Do not ask again for unavailable SDK/source code or claim that a diagnostic parser completes login; verify the bootstrap, subsequent command framing and character list.

- 2026-10-11 — A private realm can install its bootstrap through an already-known stock opcode, so absence of unhandled-opcode logs proves little. EZWoW uses 27 short 0x2E9 packets with descending counts to deliver 216 bytes to a virtual bootstrap range; record bounded payloads before ordinary dispatch and translate the verified write semantics in session memory. Return current received bytes, never a captured snapshot, and verify the subsequent loader/character-list stage separately.

- 2026-10-11 — Verify internal callback-buffer prefixes against an actual packet before inferring wire fields. EZWoW CDataStore starts with a two-byte opcode; buffer+6 skips it plus the u32 extension command. Treating all six bytes as an excluded header misread 37 bytes of library metadata as executable code. Confirm lengths and instruction bytes with a real fixture before implementing a stage.

- 2026-10-11 — EZWoW drops an early character enumeration during extension setup: a single retry after 30 seconds returned seven real characters. Verify entry into the world separately: its next command 3 updates known title mask IDs (u8 operation, u16 count, u16 IDs); implement the semantic update rather than treating it as executable code or acknowledging fictional readiness.

- 2026-10-11 — Question marks in Cyrillic names can come from absent font glyphs even when network strings are intact UTF-8. Inspect the actual font cmap before changing encoding: the local FRIZQT/MORPHEUS lack Cyrillic while ARIALN contains it. Merge a font with the missing glyphs into both the client and FrameXML faces, retain font bytes for dynamic atlas loading, and check that existing Latin glyphs keep their metrics.

- 2026-10-11 — An extension double is not necessarily a timestamp: EZWoW command 5 stores extended copper and overrides the native Lua money accessor. Verify readers, constants and related events before assigning meaning; preserve the server balance separately from truncated stock fields, validate finiteness/integrality before casting, and clear it on character/endpoint changes.

- 2026-10-11 — A diagnostic 30-second retry became visible login latency. Replace arbitrary waits with a verified protocol boundary when available: EZWoW restores its file callback to RVA 0x419210 after the manifest and DBC checks. Queue one ordinary enumeration retry, dispatch it on the main thread after pending Warden replies, and discard it if the list already arrived or the session changed. Keep the timeout only as a fallback; never skip required server checks.

- 2026-10-11 — For rendering reports, identify the running executable and its current log before quoting FPS; `wowee-fast-login.exe` used a separate log from `wowee.exe`. Compare the same interior with the stock client: preserve MOCV color variation, account for the MapObj 2× modulation, and do not multiply baked indoor light by roof/sun shadow. Check per-frame transport callbacks too: WMO transforms must refile only the moved bounds, never rebuild the entire world spatial index. The user confirmed improved lighting but incomplete parity; describe this as an improvement until a same-scene comparison verifies the remaining differences.

- 2026-10-11 — Outdoor WMO groups (including Dalaran platforms) must keep outdoor camera limits; only verified interior groups get the room cap. Do not feed smoothing lag back into the wheel target as a collision. Opaque creature/mount materials must ignore atlas alpha. Shadow normal offsets need world texel size, not normalized UV size; RT geometry distances need float32 precision at mountain ranges. Verify the reported scene before claiming visual parity.

- 2026-10-11 — Compare sky effects with the supplied stock screenshot before removing them: Dalaran has subtle aurora strands in both clients. Its 21 two-texture additive layers need the second RGB/alpha mask on UV1; a single sampler draws bright cards. Sample sky color/weight tracks at the visual day phase, resolve weight/UV combo tables, and keep global cloud fades on elapsed time. Do not bake initial zero keys or mix day, sunset and night clouds at full opacity.

- 2026-10-11 — RT precision regressions must include a rotated receiving wall in the acceleration structure, high-resolution depth, and a camera translated to continent coordinates. A low-resolution wall-depth test near the origin hid severe false AO. Keep depth reconstruction, normal differences, ray directions and reprojection camera-relative; float32 G-buffer storage alone does not fix cancellation in the inverse world-view matrix. Use geometry normals for shadow-map offsets, never texture-perturbed normals. Verify both hardware and compute tracing and distinguish the GPU regression from an actual same-scene comparison.

- 2026-10-11 — Parallel Ninja client/probe builds must isolate object files as well as response files and output executables. Another build can replace an object between LTO reads (`Cannot read application.cpp.obj`); link from stable COFF snapshots or an independent object directory. Shared `CMakeFiles/wowee.rsp` can change between linker symbol resolution and LTO, causing an internal compiler error. Preserve concurrent source changes and validate the final combined binary before replacing the primary exe.

- 2026-10-11 — For a moving-character halo, verify active graphics settings before attributing it to FSR. The user confirmed FSR is off (`upscaling_mode=0`, `fsr=0`) while RT lighting is mode 3. Inspect previous-frame RT depth matching and ambient fallback at animated silhouettes; the user confirmed that the halo disappears with RT off. An RT toggle identifies the responsible subsystem, not the exact shader defect; verify any fix on a moving/disoccluded surface before claiming resolution.

- 2026-10-11 — Terrain stripes and rectangular blend seams can be corrupt MCAL rather than UV stretching. RLE low seven bits are the exact run length (no +1); zero runs consume only the command, and decoding must stop at the current layer. Big alpha stores absolute coverage; packed alpha stores sequential opacity and needs conversion before weighted blending. Validate the real ADT loader too: local WotLK MCAL subheaders contain stale sizes such as 512 while MCNK sizeAlpha describes the full stream including its 8-byte header. Compare actual location maps against an independent decoder before tuning UVs or hiding seams with blur. Shader wind needs camera-distance fading in both the main and shadow passes; skipping distant bones alone does not stop foliage motion.

- 2026-10-11 — Change LTO concurrency only in the link command. A global `-flto=auto` replacement in generated Ninja changes compilation and invalidates the precompiled header, forcing every client object to rebuild. Preserve compile flags and output isolation when adjusting a diagnostic build.

- 2026-10-11 — Distant landmarks and transports must lose contrast into the directional atmospheric background. `LightingParams{}` retains nonzero member defaults: never use it as a weighted light/fog/sky accumulator. Start every accumulated color and distance at zero, use the sky's actual horizon/nadir band along the camera ray, and fog glass reflections after their highlights. Verify far landmarks separately from startup or shader compilation.

- 2026-10-11 — Dalaran sculpture white stripes came from M2 material handling: preserve signed texture-coordinate lookup -1 for eye-space environment mapping, and use real RGB modulation for blend modes 5/6 (including neutral fog/fade), never additive or atlas-alpha cutout. Respect signed priorityPlane too: the sculpture’s inner symbol is authored at -1 and must draw before its golden shell, while equal-priority reflection stacks keep source order. Verify the actual model and each authored layer against the stock screenshot before blaming extracted textures.

- 2026-10-11 — A screenshot showing yellow silhouettes after a fog fix means tint replacement did not solve background matching. Sky M2s can cover the procedural gradient, so use the actual composited sky for far haze, converge by the fog end, and enforce the same horizontal geometry limit on terrain and WMO groups even when portal culling is disabled. Never infer that land and buildings share a limit from a shared settings setter alone; inspect each render path.

- 2026-10-11 — “Vulkan validation layers requested” is not proof that the Khronos layer loaded: vk-bootstrap can silently omit an unavailable requested layer. Force the layer name and use a known manifest/runtime for strict GPU checks. Do not confuse loader errors from missing Epic overlay JSON files with renderer VUIDs; exclude only those exact manifest messages. Existing login timing and post-present screenshot VUIDs require a valid test path (inline command recording and in-frame readback), not blanket error filtering.

- 2026-10-11 — Fountain water is authored M2 geometry, so a world-water shader fix may miss it. Inspect the actual fountain batches, texture/UV combo tables and alpha channels. A stored batch opacity is ineffective unless both draw paths pass it to the shader; additive foam can need a second RGB/alpha mask on UV1 outside the sky renderer. Validate the real model on the GPU and distinguish material correction from a changed fountain model.

- 2026-10-11 — The user corrected a Dalaran performance fix based on batching and frame budgets: world data must actually load in the background and appear when ready. Move disk I/O, parsing, decoding and CPU compositing to bounded workers; the render thread only polls completed results and submits asynchronous GPU uploads. Never call a budgeted synchronous operation nonblocking, and prevent consumers from silently falling back to main-thread reads.

- 2026-10-11 — Immediate world-entry disconnects can be a receive-parser bug: WotLK marks five-byte server headers with the high bit of the first size byte. Decode the 23-bit size and shifted opcode, decrypt the fifth byte exactly once across TCP fragments, retain 32-bit payload lengths, and keep legacy four-byte framing. Do not diagnose a server kick from the later generic disconnect when an earlier local framing error closed the socket.

- 2026-10-11 — Background entity loaders share DBCFile instances with main-thread appearance code. The lazy ID index was unsynchronized: concurrent first lookups reproduced heap corruption immediately. Build all binary/CSV/JSON ID indexes before AssetManager publishes a table, keep lookup read-only, and test simultaneous first readers plus reload. A player-only warm-cache fixture does not prove cold world entry is safe.

- 2026-10-11 — Dalaran lamps include blended reflection overlays and a translucent light cone: drawing every M2 batch into shadow depth makes those layers opaque blockers. Use the same opaque/cutout participation rule for shadow maps and RT, and alpha-test non-foliage cutouts too. Match previous-frame RT samples by geometric normal as well as depth on thin objects. Exterior window reflections must come from surrounding geometry, never background alpha blending: make backed exterior panes opaque, retain explicit dungeon transparency, and test an offscreen reflected object on both tracing backends at continent coordinates.
